## Real data (P6 finalization, after P3/P5/P7)

`bisect serve --real` now serves this repository's actual recordings end to end. Everything below was walked page by page against a real server (`runs/index.sqlite`, `runs/ledger.sqlite`, `runs/blobs/`, `runs/blame/*.json`, `runs/p7/local/*/result.json`, `data/manifest.json`, `data/results/p5_{summary,items}.json`), not fixtures.

**Real-mode repository bugs found and fixed (small, test-first commits):**

- `RealRepository.meta()` hard-coded `tau2_commit`/`agent_model`/`user_model` as `"unknown"` even though `config/models.toml` (P0's chosen models) was sitting on disk -- now reads it via `core.models.load_chosen_models`, degrading each field to `"unknown"` only when that file is genuinely absent.
- `pr_checks()`/`pr_check_detail()` only looked in `runs/gate/<check_id>/`, which is empty (nothing has invoked `bisect gate` with its default `--out` yet); P7's own real runs used a custom `--out runs/p7/local/<check_id>` and were invisible to the PR checks page as a result. Both locations are now discovered (`runs/gate/` wins on an id collision).
- `bisect serve` had no way to find `data/` or `config/models.toml` from outside this checkout -- added `--data-dir` and `--models-config`, mirroring the existing `--runs-dir`, needed for the install proof below.
- `OverviewPayload`/`BenchmarkSummary` gained `results_split` (`bench.results`'s own `config.split`, `null` in fixture mode). The only evaluation on disk right now is the **dev** split (`docs/gates/P5.md` -- the test split did not complete; provider capacity collapse), so the UI now prints "dev split -- a diagnostic run, not the pre-registered test result" beside the Overview headline and the Benchmark method comparison.
