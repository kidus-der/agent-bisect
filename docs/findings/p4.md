# P4 finding — N = 16 and the earliest-step rule are in tension

**Headline:** the pre-registered estimator finds the planted step in **89.0%**
(178/200) of synthetic runs against a **95%** bar. Interval coverage is sound
(0.9671 at fixed N = 16, inside the [0.92, 0.98] window). The accuracy gap is
not an estimation bug; it is two known statistical costs of the pre-registered
design, and they are separable. Full evidence in `docs/gates/P4.md`.

## The two costs, measured

| | planted step found | false blames |
|---|---|---|
| fixed N = 16, single look | 184/200 = **0.920** | 0/1597 null steps (0.00%) |
| sequential, batches of 4 | 178/200 = **0.890** | 10/1597 null steps (0.63%) |

**Cost 1 — power (8 points).** With 16 draws per arm, a Newcombe interval on a
true effect of ~0.5 against a control near 0.1 frequently fails to place its
lower bound above δ = 0.10. Example from the run: treated 10/16 against control
2/16 is a point estimate of +0.375 with a lower bound of +0.053. All 16 fixed-N
misses were of this kind ("no step blamed"), none were misattributions. N = 16
therefore caps achievable accuracy at about 92% under this generative model.
**The 0.95 gate bar and the N = 16 parameter were pre-registered independently
of each other and are mutually inconsistent** — the bar was set without a power
calculation. That is the finding.

**Cost 2 — peeking under multiple testing (3 points).** Testing every step of a
~19-step run means ~8 truly-null steps ahead of the planted one, each getting up
to four looks at an uncorrected 95% interval. All nine runs lost this way were
blamed at the **first look, n = 4**, and all nine are blamed correctly under a
single fixed-N look. Arithmetic: 0.63% per null step × ~8 null steps ≈ 4.9% of
runs, against 4.5% observed.

The mechanism is the one predicted in `docs/decisions/0005-shared-control.md`:
the shared control arm correlates every step of a run, so a control that draws
0/16 (common when the control rate is near 0.05) inflates *every* step's effect
at once. Seven of the nine false blames had a shared control of 0/16 or 2/16. A
treated arm of 3/4 or 4/4 against a 0/16 control clears δ comfortably, and the
earliest-step rule then locks that first false positive in for good — a later,
correct, much stronger signal at the planted step cannot overturn it.

**Note the asymmetry the earliest-step rule creates.** It is deliberately not
symmetric: it trades false-blame risk for the guarantee that a partially-
recovering later step never masks the true cause. That trade is right on the
merits, but it means every null step *before* the true cause is an independent
opportunity to lose the run, while null steps after it are harmless. Accuracy
therefore degrades with the number of steps tested before the true fault — a
property worth reporting on real data, not just here.

## Why coverage passed while accuracy failed

Sequential coverage (0.9796) is *higher* than nominal, not lower, because an
early stop is triggered by an interval that has moved decisively away from δ,
and those intervals are wide (small N) so they still cover the truth. Peeking
damages the **decision**, not the interval. A gate on coverage alone would have
passed a procedure whose blame accuracy is 6 points short — which is a good
argument for keeping both criteria, and for never quoting coverage as evidence
that a blame rule works.

## Consequences for later phases

1. **P5 should beat 0.890, not match it.** Bisect proper tests a judge shortlist
   of m = 3, not ~19 steps. Roughly 2 null steps instead of 8 cuts the
   false-early-blame exposure about fourfold. The judge shortlist is not only a
   cost saving — it is also multiplicity control. Conversely, the all-steps
   configuration used as an upper-bound baseline will carry this penalty.
2. **The no-control ablation will look artificially strong on accuracy here.**
   Without a control arm the effect is just the treated pass rate, so a 0/16
   control cannot inflate anything and the correlated-false-blame mode vanishes.
   It will instead be badly biased whenever the control rate is not ~0, which
   this generator's control range (0–0.15) partly masks. Report its bias, not
   only its accuracy.
3. **Decide N with a power calculation before P5, in the open.** Achieving 95%
   at δ = 0.10 against these effect sizes needs more than 16 per arm, or a
   minimum-N rule before a step may be declared blame-worthy. Either is a
   pre-registration change that must be written down *before* P5 data is seen,
   with its cost consequence stated (N is linear in API calls).
4. **P4 does not validate the shared control.** The generator makes the control
   pass probability a single per-run number, so the flat-control assumption
   holds here by construction. `control_mode="per_step"` exists and is tested;
   P5 must actually run the comparison on real recorded failures.

# Update after fix attempt 1: the peeking defect is gone, the ceiling is not

Everything above is the original result and stands. Fix attempt 1 replaced the
uncorrected interim test with an O'Brien–Fleming efficacy boundary for K = 4
looks at overall two-sided α = 0.05
(`docs/decisions/0008-sequential-efficacy-boundary.md`, committed before the
re-run). Result on the same master seed:

| | uncorrected | OBF boundary |
|---|---|---|
| planted step found | 178/200 = 0.8900 | 179/200 = **0.8950** |
| false blames (earlier + later) | 11 | **0** |
| null-step false-positive rate | 0.63% | **0.00%** |
| coverage, fixed N = 16 (gated) | 0.9671 | 0.9671 (unchanged) |

**Cost 2 from the original analysis is fully resolved and it bought almost
nothing.** Zero false blames on both the master seed and the pre-declared
confirmation seed 20260918 (which scored 0.9300, also FAIL). But of the 11 runs
rescued from a false blame, 10 simply became non-detections: the stricter final
look (z = 2.024 rather than 1.96) fails to detect their planted step too. Net
movement: +0.005. **Correcting a real statistical defect changed the verdict not
at all** — which is itself the most useful thing P4 has to say about the design.

## Power table — why N = 16 is the binding constraint

Exact enumeration over both binomials at N = 16 per arm (no simulation, no
seed): the probability that the nominal 95% Newcombe lower bound exceeds
δ = 0.10. Reproduce with `uv run python scripts/gates/p4.py --power-table`.

| control ↓ / treated → | 0.60 | 0.70 | 0.80 | 0.90 |
|---|---|---|---|---|
| **0.00** | 0.981 | 0.998 | 1.000 | 1.000 |
| **0.10** | 0.717 | 0.881 | 0.968 | 0.997 |
| **0.15** | 0.552 | 0.761 | 0.915 | 0.988 |

At the OBF final look (z = 2.024, conf 0.9570) the same cells read 0.942 / 0.993
/ 1.000 / 1.000, 0.658 / 0.852 / 0.962 / 0.997, and 0.497 / 0.732 / 0.908 /
0.987.

Read the bottom-left corner: a real effect of +0.45 (treated 0.60 against
control 0.15) is detected barely half the time. The P4 generator draws treated
uniformly on [0.60, 0.95] and control uniformly on [0.00, 0.15], so a
substantial minority of runs live there, and the achievable found rate is capped
near 0.92 — below the 0.95 bar before a single line of estimator code runs.

**For P5 and the report:** this table is the number to cite when choosing N. A
0.95 accuracy target at δ = 0.10 requires either more re-runs per arm or a
larger minimum detectable effect; it cannot be obtained from a better estimator.
Note also that cost is linear in N, so the trade is explicit: N = 16 costs
`(m + 1) × 16` re-runs per diagnosis and buys ~0.92 accuracy on effects of this
size. Any change to N is a pre-registration amendment and must be written down
before P5 data is seen.
